## 4. 限定与解读(诚实说明)

1. **行数是最弱的生产率指标**。更有含金量的是节奏指标:一个完整里程碑循环——grill 设计共识 → ADR 落桩 → 出票(GitHub Issues + 阻塞依赖)→ 并行实现(worktree 隔离)→ 实质性 review(如 DDS `LastError` 语义纠偏、死锁测试修复)→ 文档回填 → 打 tag——压缩到半天~一天,且 master 全程保持绿。传统流程中该循环以周计。
2. 倍数的真实来源是 **AI agent 并行实现 + 人把守设计决策与验收门**,而非打字速度。设计期占一半活跃天,这部分没有省也不应省——P1–P4 能一天两期,正是吃了前期 grill 出来的清晰任务边界的红利。
3. **未计入**:两个站着的测试技术债(CGNAT flake、`FakeDdsProvider` 静态总线 repeat artifact)与整个 P6(性能/容量/两机验收、24h 稳定性)——验收类工作的"行数产率"天然低,全程平均应待 P6 完成后复核。
4. 期间有 ≈6,900 行删除量(目录重组、合并冲突修复、#98 清理),存在真实返工,非纯堆行数。
