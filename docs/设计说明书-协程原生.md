- **谁读**:实现者（据本文件逐期落地）、`/to-tickets`（据路线图拆票）、评审（据追溯核对 RT_*）。
- **如何用**:
  1. 路线图（§4）是主线。`/to-tickets` 对某一期展开为一组有序票；复杂期可先 `/to-spec` 细化该期再拆票。
  2. 每期以其 RT_* 追溯 + 验收门槛（§4）为完成定义。

- **权威边界**:可观察/可验收行为以 SRS 为准；本文件冲突时以 SRS 优先。类名/签名/容器/锁等落地形态属本 SDD，可随实现细化。

## 2. 整体设计

### 2.1 三层与缝

沿用 SRS §1.2 三层解耦,目标架构下各层与**缝**（seam，可测替换点）如下:

```
宿主应用
  │  公共 API：node 组合、配置、codec 装配、handler 注册、结果与可观测（RT_IF_API）
  ▼
node（交互层，transport::ProtocolNode / transport::DdsNode）
  │  ├─ 组合：ITransport（内部缝）+ ICodec（公共扩展点）+ PendingTable（内部机制）
  │  ├─ 读-分发循环（内联各 node，非独立引擎 —— RT_DESIGN_003）
  │  └─ 请求关联 / 入站有界队列 / 生命周期 / 连接状态观察
  ▼
Codec（公共扩展点，ICodec）        Transport（内部缝，ITransport）
  逻辑消息 ↔ 线缆字节                纯字节/样本收发（TCP/UDP/串口/DDS）
```

- **`ITransport`（内部缝，非用户 API —— RT_IN_INTERFACE_002）**:`Start / Read(options) / Write(SendUnit) / RequestClose / WaitClosed`。介质无关拉模型:`Read` 一次一片（流式任意切片 / 报文一整报）。发送完成语义见 RT_TRANSPORT_008，并发写按到达顺序串行化（RT_TRANSPORT_007，已实现见 §4 P1）。实现:`TcpTransport`（已建立连接）、`TcpClientTransport`（外层连接管理，P3）、`UdpTransport`/`SerialTransport`/`DdsTransport`（P4）。
- **`ICodec`（公共扩展点 —— RT_CODEC）**:`Encode(逻辑消息)→完整帧` / `Decode(输入)→0..N 逻辑消息`。流式跨切片拼帧、报文式保边界；坏帧诊断 + 重同步。由应用装配到 node。
- **`PendingTable`（内部机制，非引擎 —— RT_IN_INTERFACE_004 / ADR-0001 D2）**:纯挂起-应答原语（唯一登记 / 恰好一次完成 / `failAll` 全部收敛 / 取消纪律 / `conn:` vs `timeout:` 区分）。**读循环、decode、算 key、判终结、发送模式全部内联各 node**，不得塌回 engine+policy。
- **DDS provider 交接边界（内部缝 —— RT_IN_INTERFACE_003 / RT_NODE_004/007）**:有界、非阻塞 listener、同 topic 保接受顺序地把样本交入节点执行域;不要求名为 `DdsBridge` 的组件。provider 适配（`IDdsProvider` / Fake / FastDDS）在其下。

### 2.2 node 如何组合（无共享引擎）

`ProtocolNode`/`DdsNode` = **薄壳组合**,不继承框架类型、不共享交互引擎:

- 持有一个 `ITransport` + 一个装配的 `ICodec` + 一个 `PendingTable`;
- 跑一条**读-分发循环 fiber**(RT_NODE 行为过程):`Read() → Decode() → 优先请求响应匹配(PendingTable) → 未匹配业务消息入有界队列 → 处理器 fiber 串行消费`;
- 协议可观察语义(五种交互模式、心跳、周期、pub-sub)由**各 node 自实现**(RT_NODE_003);公共只复用 `PendingTable` 的关联纪律与生命周期收敛。

### 2.3 线程与执行域模型

- **AsyncTask 强制运行时**(RT_DESIGN_002):不设 `IExecutor`/`ThreadExecutor`。M:N 协作式:不同 node 可并行,同一 node 的状态变更/关联/入站处理**串行**(RT_CORO_RUNTIME_004)。
- **节点所属执行域**:node 首次成功启动绑定稳定执行域,运行期不迁移(RT_CORO_RUNTIME_003)。公共异步操作可从任意 fiber 发起并转交所属域(RT_CORO_RUNTIME_005)。
- **底层回调不碰节点状态**:Qt I/O 事件在 socket 的 QThread、DDS 样本在 provider listener 线程,均须安全转交执行域,不在回调线程执行业务处理器(RT_HANDLER_002)。`ITransport` 复用 corosocket awaitable;DDS 单设线程交接边界。
- **控制优先级**(RT_NODE 3.1.9.4):关闭/取消/代际切换 > 请求响应匹配 > 普通业务 > Trace。仅约束可观察结果。

### 2.4 生命周期与连接状态(两个独立轴)

- **节点生命周期**(全介质通用):`Created → Running → Closing → Closed`(RT_LIFECYCLE_001),幂等并发安全的启动/关闭、多等待者完全关闭。
- **TCP 物理连接状态**(仅 TCP 客户端,`Running` 内子状态):`Disconnected/Connecting/Connected/Reconnecting` + 连接代际(RT_LIFECYCLE_002)。**非重连节点**(TCP 服务端连接/UDP/串口/DDS)无 `Reconnecting`,底层致命错误 → `Closing→Closed`。分层归属见 ADR-0002 D3/D3′。
- **健康裁决三层**(ADR-0002 D3):传输报 **I/O 事实**(最近收发时间戳/计数/单操作错误);`TcpClientTransport` 管**物理连接状态**;node 各自做**协议判活裁决**(心跳+超时;DDS 用 Liveliness QoS)。

## 4. 分期路线图

原则:纵向薄切片优先(Q2);每期一个可测边界;验收 = Fake 契约 + 单机真实介质回环 + RT_* 追溯(两机/性能/24h 归 P6)。

### P0 — 清理 + 目标骨架落位

- **范围**:按 §3.2 删旧、改造沿用、提升命名空间到 `transport::`;单一 `transport` CMake 目标;更新 SRS 引用/CHANGELOG/README。
- **RT_***:RT_DESIGN、RT_IN_INTERFACE。
- **依赖**:无(起点)。
- **验收**:干净构建零告警;保留的目标测试(含 #19 发送语义)全绿;仓库无 as-built 架构残留。
- **关联**:承接已合并的 #19(TcpTransport 发送语义 + 读路径)。

### P1 — 首纵切片:TCP 上最小请求-响应

- **范围**:补完 `TcpTransport` **读侧契约**(足够 node 读循环:一次一片、来源=对端、背压/关闭/超时映射,遗留项 A);移植一个流式 codec(`SystemCodec`,占位帧常量)到目标 `ICodec`;**内联 `PendingTable`**(唯一登记/恰好一次完成/`failAll`/取消纪律);最小 `ProtocolNode`(仅 `needresponse` + 读-分发循环);TCP 回环端到端一次请求-响应。
- **RT_***:RT_REQUEST(核心)、RT_NODE(骨架 + RT_NODE_003)、RT_HANDLER(最小)、RT_LIFECYCLE(基础)、RT_CODEC(流式)、RT_IN_INTERFACE_004。
- **依赖**:P0。
- **验收**:Fake 传输 + 真实 TCP 回环上,`ProtocolNode` 完成一次 needresponse 请求-响应,恰好一次完成 + 关联清理;乱序/迟到响应被丢弃并观测。
- **意义**:**证实"无共享引擎、语义内联各 node"这一最大架构赌注**。
- **交付**:✅ 已交付(#34 读侧契约 / #35 PendingTable / #36 ProtocolNode / #37 TCP 回环端到端);全量测试 95→119 全绿,架构赌注在真实 TCP 回环上证实。精确签名回填见 §6。

### P2 — 节点加厚:入站处理器 + 有界队列 + 生命周期

- **范围**:入站业务处理器(组合注册,串行,协作取消 —— RT_HANDLER 全);有界业务队列(默认 1024 事件/16 MiB,溢出 tail-drop + `ResourceExhausted`,优先级 —— 3.1.5.4);完整节点生命周期(幂等启动/关闭、多等待者完全关闭、处理器可发起关闭不自锁 —— RT_LIFECYCLE 全);可定义的交互模式(`noresponse`/`needresponse`/`withfeedback`/`needfeedback`/`repeating` 的可落地部分,精确状态机受 TBD-001 约束,以占位推进)。
- **RT_***:RT_HANDLER、RT_LIFECYCLE、RT_REQUEST_006(≥256 在途)、RT_NODE_001/002(部分)。
- **依赖**:P1。
- **验收**:Fake 上验证 256 并发在途 + 乱序响应恰好一次完成、队列溢出 tail-drop、关闭协作取消收敛;真实 TCP 回环冒烟。
- **交付**:✅ 已交付(#47 BoundedQueue / #48 256+session_id LRU / #49 handler+队列+Send / #50 生命周期硬化+TCP 冒烟);全量测试 119→152 全绿。精确签名回填见 §6。**留 P2 之外**:`withfeedback`/`needfeedback`/`repeating` 精确状态机(TBD-001)、server 自动应答、连接代际退休(P3);pre-start `SetConfig` 原地改配(RT_LIFECYCLE_007 以"失败停 Created 可重试"体现,完整改配 API 后补)。

### P3 — 连接管理（TcpClientTransport）

- **范围**:外层 `TcpClientTransport`(实现 `ITransport` + 客户端扩展)owns socket,组合内层 `TcpTransport`(P1);连接状态机 + 连接代际 + 自动重连(退避 1s×2 上限 30s ±20%)+ 运行时重配置(单调版本、原子应用);断连即时终结在途请求(RT_TCP_RECONNECT_002)。见 seed **#20**。
- **RT_***:RT_TCP_RECONNECT、RT_TCP_RECONFIG、RT_LIFECYCLE_002、RT_DATA_STATE。
- **依赖**:P1(内层)、P2(节点生命周期)。
- **验收**:Fake 代际隔离(旧代际迟到事件不污染新代际)、重连退避、重配置端点切换;真实 TCP 断连-重连回环。
- **注**:corosocket `connectToHost` 无超时且 await_for 不取消底层 connect → 须显式 `abort()` 管理每次尝试(ADR-0002 摩擦点)。

### P4 — 其余介质

- **RT_***:RT_TRANSPORT 全、RT_NODE_004/005/007、RT_IF_UDP/SERIAL/DDS、RT_IN_INTERFACE_003。
- **依赖**:P1(节点/缝复用)、P2。
- **验收**:各介质 Fake + 单机真实回环(UDP loopback / 串口 PTY / 进程内 FakeDdsProvider;Fast DDS 可选跳过真实但不跳 provider 契约)。

### P5 — 观测 + 完整性归因

- **范围**:可插拔结构化 Trace + 指标全量出口(RT_TRACE,覆盖连接/代际/收发/解码/关联/超时/取消/溢出/处理器/重连/关闭);**命名丢弃原因计数器**(业务队列溢出/DDS 交接溢出/坏帧/迟到·重复·无匹配响应/关闭丢弃/连接代际隔离丢弃 —— D6);**loss=0 验证 harness**(容量内损失类计数器全 0、Σ命名原因=总丢弃);I/O 事实观测面统一(遗留项 B)。

- **[P2 已回填]** P2 新增稳定签名 —— `BoundedQueue<T>`(协议无关有界队列:`Push`/`Pop`/`Close`/`Drain`,双上界 + 注入 `byte_size_of`,见 `include/transport/BoundedQueue.hpp`,供 P4 DdsNode 复用 D10)、`InboundHandler = Status(const Message&, HandlerContext&)` + `HandlerContext`(露 `Send`/`RequestClose`/`cancellation()`)、`ProtocolNode::Send(Message)`(noresponse)、session_id 空闲集 LRU 分配器(内联 ProtocolNode)、`PendingTable` 可选 `max_pending`。生命周期硬化:并发幂等 Start(`start_done_` 共享结果)、三方汇合(读循环+handler+FailAll,独立 finalizer fiber 驱动)、重入自锁防护(比对 `boost::this_fiber::get_id()`)。**pre-start `SetConfig` 原地改配未做**(RT_LIFECYCLE_007 以"失败停 Created 可重试"体现)。
- `PendingTable` 是否需同 key 并发多待(当前 `(session_id,message_id)` 键空间不需要 —— ADR-0001 遗留)。
- `PendingTable` 当前是"单终结响应"关联模型(首次完成即终结 erase);P2 的 `withfeedback`/`needfeedback`(中间反馈多次 + 最终结果终结)需评估**扩展基座加"通知但不终结"原语**还是**node 侧另开反馈通道**——受 RT_DESIGN_008 约束,反馈的协议语义不得漏进协议无关基座。
- **[P1 已落地]** socket 的 QThread ↔ 节点执行域 绑定机制(RT_IN_INTERFACE_005):单 fiber 调度器下 `TcpTransport` 复用 corosocket(已在 fiber 调度器内推进),无需跨线程交接;node 交互状态经 `std::mutex` 串行化(ADR-0003 D8)。真正的多执行域 / affinity 调度硬化与 DDS listener 跨线程交接留后续期(P4/更后)。
- DDS provider 交接的具体投递机制/容量与 DDS QoS 一致性(P4 正式 DDS 集成需求收口)。
- 五模式状态机、帧常量、性能基线(外部依赖,§4.1)。
