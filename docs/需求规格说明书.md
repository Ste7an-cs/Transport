# 通信中间件框架 — 需求规格说明书（SRS）

**版本：** 2.0（0.2.0 开发线，as-built 整理）
**日期：** 2026-06-23
**配套文档：** 《设计说明书》`docs/设计说明书.md`

本文件汇总框架的**需求**（做什么、必须满足的约束），由 `docs/superpowers/specs/` 的逐特性设计文档与当前代码实现整理而成，作为单一权威需求参考。设计与实现细节见配套《设计说明书》。

> **架构基线变更（vs 1.0 / 0.1.0）：** 0.2.0 把原先臃肿的富 `ITransport` 拆为**三层解耦**——**Transport（纯字节管道）/ ICodec（线缆格式：分帧+序列化+交互元数据）/ Comm（交互节点：请求-应答等模式，用户继承）**。0.1.0 的 `TransportCore`、三模式接收（`Receive`/`OnReceive`/`AsyncReceive`）、`IFramer`/`LengthFieldFramer`、`TopicEnvelope`/topic 路由、`TransportFactory`、DDS `RawMessage`/`SendRequest`、`ITcpServer` 等**均已移除**；`v0.1.0` 标签保留旧实现备查。本 SRS 描述 0.2.0 当前状态。

## 1. 引言

### 1.1 目的
定义一个 C++17 通信中间件库的功能与非功能需求。该库把**传输**、**编解码**、**交互模式**三者解耦:Transport 跨多种介质（TCP / UDP / 串口 / DDS）收发**原始字节**;ICodec 在收发边界把 `Message`↔线缆字节(分帧+序列化+交互元数据);Comm 层节点在 ICodec 之上实现请求-应答 / 结果反馈 / 发布-订阅等交互模式,供用户继承获得通信能力。

### 1.2 范围
- **是：** 一个可静态/动态链接的三层通信库——纯字节管道 + 可插拔线缆格式 + 可继承的交互模式节点;线程模型经 `IExecutor` 可换。
- **不是：** 消息代理 / 路由守护进程;不规定业务语义(payload 字节由用户解释)。

### 1.3 术语
| 术语 | 含义 |
|---|---|
| Transport（传输） | 纯字节收发管道的统一抽象（`ITransport`），不知 Message/codec/交互 |
| ICodec | 线缆格式扩展点:`Encode(Message)→bytes` / `Decode(bytes)→0..N Message`,负责分帧+序列化+承载交互元数据 |
| Message | 一条消息的数据模型(payload + 交互元数据 kind/correlation_id/topic/reply_to + 协议字段) |
| Comm 节点 | 第三层:在 Transport+ICodec+IExecutor 之上实现交互模式的类(`CommNode`/`DdsNode`/`ProtocolNode`) |
| Endpoint | 中立寻址目的地值类型（`Default` / `Net(ip,port)` / `Topic(name)`） |
| IExecutor | 执行器缝:决定业务回调在哪/怎么跑 + 定时(`ThreadExecutor` / 测试 `InlineExecutor` / 未来 `CoroExecutor`) |
| provider | DDS 底层库的抽象适配（`IDdsProvider`），如 Fast DDS / 进程内 `FakeDdsProvider` |

---

## 2. 总体描述
- **平台：** Linux（桌面/服务器）。**语言：** C++17,不抛异常。
- **使用场景：** 本机进程间 + 跨网络（混合）;点对点请求-应答、DDS 发布-订阅、对接外部系统的具体协议。
- **集成：** 静态/动态库,应用层直接链接;所有节点/传输以 `std::shared_ptr` 持有。
- **核心假设：** payload 字节语义由用户负责;框架负责字节搬运、线缆编解码、交互模式编排与线程/定时。

## 3. 功能需求

### FR-1 传输层（纯字节管道 `ITransport`）
- **FR-1.1** 所有传输实现统一的 `ITransport`:生命周期（`Open`/`Close`/`IsOpen`）、`Send(bytes)` / `Send(bytes, Endpoint)`、回调式交付 `OnBytes` / `OnConnect` / `OnDisconnect`。**不**涉及 Message/codec/分帧/交互。
- **FR-1.2** 交付为**回调式**:`OnBytes(Result<vector<uint8_t>> bytes, string from)` 由各传输 io 线程(绑 strand)串行调用,必须非阻塞;`from` 为来源标识("ip:port"/topic/设备路径)。一次回调:报文式(UDP/DDS)= 一个完整 datagram/sample;流式(TCP/串口)= 本次 read 到的字节切片(切帧由上层 ICodec 负责)。
- **FR-1.3** `Send` 返回的 `Status` 表示入队/写出成功,不代表对端已收。
- **FR-1.4** 错误分流:UDP 收/发单包 I/O 错误经 `OnBytes` 投 `Result::Fail`(不致命,继续);TCP/串口连接级读写错误走 `OnDisconnect`。

### FR-2 寻址发送（Endpoint）
- **FR-2.1** 中立寻址值类型 `Endpoint`(`Default` / `Net(ip,port)` / `Topic(name)`),零第三方依赖,与 `Message.topic`/`source` 对称(收到可据其回发)。
- **FR-2.2** `Send(bytes, Endpoint)`:`kDefault` 用 config 默认目的地;UDP 处理 `kNet`、DDS 处理 `kTopic`;不适用组合返回 `config:` 错误(如 DDS 收 `kNet` → `config: dds expects topic endpoint`)。

### FR-3 编解码层（线缆格式 `ICodec`）
- **FR-3.1** `ICodec` 提供 `Encode(const Message&) → Result<vector<uint8_t>>`(一条消息→一段线缆字节,一对一)与 `Decode(const uint8_t*, size_t) → Result<vector<Message>>`(喂入字节切片→切出 0..N 条完整消息)。
- **FR-3.2** `Decode` 可**有状态**(流式滚动缓冲,由单一 io 线程喂,如 `SystemCodec`/`LengthFieldCodec`)或**无状态**(每段即一条完整消息,多线程并发安全,如 `DatagramCodec`/`DdsCodec`)。
- **FR-3.3** 内置 codec:
  - **`SystemCodec`** —— 某外部系统的**协议帧**(见 FR-12):`AA BB CC DD` 同步头 + 协议字段 + 注入 CRC + 有状态流式 + 坏帧 resync。
  - **`DdsCodec`** —— 无状态、带交互元数据(`kind`/`correlation_id`/`reply_to`)的 DDS 线缆格式(每 sample 一条完整消息)。
  - **`LengthFieldCodec`** —— 长度字段分帧的通用流式 codec。
  - **`DatagramCodec`** —— 报文直通(整段即一条 `kOneway`,header-only)。
- **FR-3.4** 解析错误以前缀分类:坏帧头/越界 → `frame:`;序列化/字段错误 → `codec:`。流式 `frame:` 不可恢复语义由消费方(Comm 节点)决定终结或继续。

### FR-4 执行器缝（`IExecutor`）与线程模型
- **FR-4.1** `IExecutor` 抽象「业务回调在哪/怎么跑」+ 定时:`Start`/`Stop`(drain+join)、`Post(Task)`(投递到业务上下文【串行】执行,容量满时【阻塞调用方】=背压)、`ScheduleAt(deadline, Task)→TimerId`、`Cancel(TimerId)`(幂等)。
- **FR-4.2** 内置 `ThreadExecutor`:1 条 worker 线程 + 有界任务队列(满则阻塞=背压)+ 最小堆定时器;Comm 节点逻辑与执行器**无关**,可在 `ThreadExecutor` / 测试 `InlineExecutor`(确定性、同步)/ 未来 `CoroExecutor`(自研协程)间不改动地换。
- **FR-4.3** io 线程内联 `Decode` → `executor->Post` 投递业务上下文 → 单 worker 串行执行回调/分发(背压点在 `Post`)。

### FR-5 交互模式基类 `CommNode`（通用点对点）
- **FR-5.1** 用户继承 `CommNode` 获得通信能力,持有任一 `ITransport` + `ICodec` + `IExecutor`。
- **FR-5.2** 交互模式:单向 `Send`;请求-应答 `Request`(回调重载 / `std::future` 重载);请求-结果反馈(中间 `kFeedback` 多次 + 终结 `kReply`);服务端 `OnRequest(req, Responder)`,`Responder.Reply/Feedback` 回送。
- **FR-5.3** 按 `MessageKind`{kOneway,kRequest,kReply,kFeedback,kNotify} 统一分发;请求用 `correlation_id`(字符串)配对,经 `executor->ScheduleAt` 超时;断连终结全部挂起请求;reply 与超时**恰好一次**。
- **FR-5.4** 并发与生命周期:posted 任务/transport 回调捕获 `weak_ptr` 防悬空;`Encode`+`Send` 在锁外(避免与同步执行器回环死锁);`Close()` 先终结挂起再 `executor->Stop()`;`Open()` 经基类句柄调用须多态(`Open` 为 virtual)。

### FR-6 DDS 交互节点 `DdsNode`
- **FR-6.1** `DdsNode : CommNode`,复用交互引擎,加性补 DDS 能力:`Subscribe`/`Unsubscribe`(转发 `IDdsTransport`);发布即 `Send(msg, Endpoint::Topic(t))`、请求即 `Request(..., Endpoint::Topic(req_topic))`(不增冗余方法)。
- **FR-6.2** 多 topic:一个 DdsNode 可发布/订阅多个 topic;入站消息 `topic`/`source` 取来源 topic。
- **FR-6.3** 多路请求-应答:请求把自身 **inbox topic** 写入 `Message.reply_to`(随 `DdsCodec` 上线缆),服务端 `Responder.Reply` 据 `reply_to` 精确回送发起方 inbox;`correlation_id` 配对。`Open()` 自动订阅本节点 inbox topic。

### FR-7 外部协议节点 `ProtocolNode`
> 见 FR-12（帧格式）。独立节点,复用 `ITransport`+`ICodec`(默认 `SystemCodec`)+`IExecutor`,不继承也不改 `CommNode`。
- **FR-7.1** 5 种发送交互模式,每条消息属其一:`noresponse`(发后即完)/ `needresponse`(等 RESPONSE)/ `withfeedback`(等 RESULT)/ `needfeedback`(收 RESPONSE→收 RESULT→自动回 RESPONSE ack)/ `repeating`(可配间隔定时发 STATE,显式停或关节点停)。
- **FR-7.2** 匹配键 **(session_id, message_id)**:应答帧原样回填请求的 session_id + message_id。超时**重发** COMMAND ≤ `max_retries`(默认 3)后失败 `timeout:`。
- **FR-7.3** 收发**双角色**:作为接收方收 COMMAND → `OnCommand(msg, Responder)`,应用用 `Responder.Response()/Result()` 回。
- **FR-7.4** 周期心跳:`heartbeat_interval_ms > 0` 时 `Open()` 起定时器周期发 HEARTBEAT;入站 HEARTBEAT → `OnHeartbeat`。

### FR-8 TCP 传输
- **FR-8.1** 客户端 `TcpClientTransport`(实现 `ITransport`):连接 `host:port`,连接超时 `connect_timeout_ms`,`auto_reconnect`(指数退避自动重连,重连仍触发 `OnDisconnect`/`OnConnect`)。
- **FR-8.2** 已连接 socket 收发为 `TcpConnection`(实现 `ITransport`,client 与 accepted 共用)。
- **FR-8.3** 服务端 `TcpServerTransport`(**独立接受器,非 `ITransport`**):监听 `bind_addr:port`(`backlog`),每 accept 造一个 `TcpConnection` 经 `OnAccept(shared_ptr<ITransport>)` 交付,用户在每连接上独立收发;`OnError` 通知接受错误;`LocalPort()` 取回 OS 分配端口。

### FR-9 UDP 传输
- **FR-9.1** `UdpTransport` 单类支持单播 / 组播 / 广播(`UdpMode`);`Send(bytes)` 发往默认目的地(单播/广播=`remote_addr:remote_port`,组播=`multicast_group:remote_port`)。
- **FR-9.2** 运行期寻址 `Send(bytes, Endpoint::Net(ip,port))`;接收 `from` 含发送方 "ip:port";组播可配 TTL、本地绑定 `local_addr:local_port`。

### FR-10 串口传输
- **FR-10.1** `SerialTransport`:设备路径、波特率、数据位、停止位(1/2)、校验('N'/'E'/'O');字节流语义,切帧由上层 ICodec。

### FR-11 DDS 传输（纯字节管道）
- **FR-11.1** `IDdsTransport : ITransport`(加 `Subscribe`/`Unsubscribe`);`DdsTransport` 持有 `IDdsProvider`,一实例 = 一 `DomainParticipant`(`domain_id`)。
- **FR-11.2** `Send(bytes, Endpoint::Topic(name))` → publish(`Send(bytes)` 无 endpoint → `default_topic`);`Subscribe(topic)` 后样本到达直接在 provider listener 线程调 `OnBytes(bytes, from=topic)`(**同 topic 有序、跨 topic 并发**)。
- **FR-11.3** **req-resp 不在传输层**:DDS 传输仅纯字节 pub-sub,请求-应答/关联/超时全部上移到 `DdsNode`(FR-6)。
- **FR-11.4** provider 抽象 `IDdsProvider` + `DdsProviderRegistry`(按名)+ `FakeDdsProvider`(进程内内存 topic 总线,共享 `Bus` DI,零 FastDDS 依赖即可全测)+ 可选 `FastDdsProvider`(Fast DDS 2.13,手写 `FastDdsRawType` 绕过 IDL/CDR)。`DdsConfig` = `{domain_id, default_topic, provider, qos:DdsQos{reliability,durability,history_depth}}`。

### FR-12 外部协议帧格式（`SystemCodec`）
- **FR-12.1** 线缆(小端)：`[head_flag:4=AA BB CC DD][frm_type:1][protocol_id:1][session_id:1][reserve:4=0][crc:2 LE][frm_len:2 LE][frm_body: message_id:2 LE | payload]`。头固定 15 字节;`frm_len = 2 + payload_len ≤ 65535`(超限编码报 `frame:`)。
- **FR-12.2** `frm_type` 枚举:`COMMAND`/`RESPONSE`/`RESULT`/`STATE`/`HEARTBEAT`/`UNKNOWN`;`protocol_id` 区分对接的外部系统(按节点配置);匹配键 (session_id, message_id),`message_id` 为 body 前 2 字节。
- **FR-12.3** CRC 经 **`CrcFn` 注入**(构造传入,默认占位 `DefaultCrc16`),校验整个 `frm_body`;有状态流式解码,坏帧(同步头/CRC 不符)→ **resync**(前移 1 字节重扫,不报致命错)。
- **FR-12.4** `frm_type` 六类的真实字节值与 CRC 真实算法为**外部常量**,经枚举占位 + 注入接口预留,接入前替换,不改结构。

### FR-13 错误模型
- **FR-13.1** 框架不抛异常;所有可能失败的操作返回 `Result<T>` / `Status`,类型标 `[[nodiscard]]`。
- **FR-13.2** 错误前缀:`timeout:` / `conn:` / `codec:` / `frame:` / `io:` / `config:`。

## 4. 非功能需求
- **NFR-1 语言/标准：** C++17;CMake;Google C++ 风格;不抛异常,统一 `Result<T>` 错误通道(`[[nodiscard]]`)。
- **NFR-2 三层解耦：** Transport 不依赖 Message/ICodec;ICodec 不依赖任何具体 transport;Comm 节点只依赖 `ITransport`/`ICodec`/`IExecutor` 接口(+ 同层默认 `SystemCodec`/`ThreadExecutor`),不碰具体 provider/transport 实现。
- **NFR-3 并发模型：** 各传输实例内部一个 io 线程(绑 strand,`OnBytes` 串行);Comm 层 io 线程内联 Decode → `executor->Post` → **单 worker 串行**业务回调,背压在 `Post`;posted 任务/回调捕获 `weak_ptr`;`Close` 先终结挂起/取消定时器再 `executor->Stop()` 再关传输,保证无回调在节点析构后跑。
- **NFR-4 线程模型可换：** 经 `IExecutor` 缝,线程模型(线程/协程/确定性测试)可换而不改 Comm 节点逻辑。
- **NFR-5 抽象层零第三方依赖：** `include/transport/` 只含纯接口 + 数据结构;asio / Fast DDS / termios 封在实现层/`src/`。
- **NFR-6 可扩展/可替换/可测：** 经 `I*` 接口换实现、用 fake 测上层;DDS 经 `IDdsProvider` 接新库;Comm 节点用 `FakeTransport`(进程内回环)+ `InlineExecutor`(确定性)端到端可测,且同套交互测试在真实 `ThreadExecutor` 下复跑验证可换性。
- **NFR-7 自包含离线构建：** asio 1.30.2 / nlohmann json 3.11.3 / googletest 1.14 vendored 进 `third_party/`,零联网。
- **NFR-8 可选 DDS：** Fast DDS 2.13+ 为唯一可选外部依赖,`find_package` 自动探测;未装跳过 `FastDdsProvider` 及真实互通测试(DDS 业务仍可用 `FakeDdsProvider` 全测)。

## 5. 外部接口需求
- **5.1 库 API：** 公共头文件 `include/transport/*`(接口 + 数据结构 + 配置),不含第三方类型。三层目录:transport 层根 + `tcp/`/`udp/`/`serial/`/`dds/`;codec 层 `codec/`;comm 层 `comm/`。
- **5.2 第三方库：** standalone Asio ≥1.28(TCP/UDP/串口);Fast DDS 2.13+(可选);GoogleTest ≥1.14(测试);POSIX termios(串口)。

## 6. 约束与假设
- 仅 Linux;C++17;Google 风格;不抛异常。
- 节点/传输须以 `std::shared_ptr` 持有(`enable_shared_from_this` + weak_ptr 保活)。
- `ProtocolNode` 同一时刻未决请求受 (session_id, message_id) 键空间约束(双计数器每发自增,2^24 realign);外部协议的 `frm_type` 真值与 CRC 算法须接入前经注入接口提供,两端一致。
- DDS 多 topic req-resp 依赖 `reply_to` 上线缆(`DdsCodec`),对端须为同框架 `DdsNode`。

---

## 7. 范围外（YAGNI / 后续）
- 自研协程 `CoroExecutor`(本轮只留 `IExecutor` 缝 + `ThreadExecutor`)。
- `ProtocolNode` 的 `noresponsewithcheck` 模式、多外部系统路由表、QoS 细配、分帧(payload>65533 直接报错)。
- 配置驱动工厂、抽象 `INode`(已评估,当前以 `CommNode` 为公共基类型、不引入)。
