# 通信中间件框架 软件需求规格说明（协程原生架构）

**版本：** 协程原生目标架构 · 草案 v1
**日期：** 2026-07-17
**状态：** ⚠️ 本文件描述**协程原生目标架构**，为前瞻性需求；**超出 as-built v0.3.0 当前实现**（当前实现仍含 `IExecutor`/`ThreadExecutor`、`InteractionEngine`/`InteractionPolicy` 抽象与 QtNetwork 回调式 `ITransport`）。本 SRS 定义目标：以 AsyncTask 协程运行时取代执行器抽象；**保留 `ITransport` 抽象但改为协程 await 式**、具体实现薄包 coro socket（DDS 经桥实现同一抽象）；**不设独立交互引擎/策略抽象，各 node 自实现所需交互模式**。
**配套文档：** 《设计说明书》`docs/设计说明书.md`、《变更日志》`CHANGELOG.md`

> **章节标识符说明：** 各章节名称后括号内为该章节唯一标识符。前缀 `RT` 表示「需求-Transport（本框架）」；子条目沿用父章节前缀派生。

## 1. 范围

### 1.1 标识

- **软件名称：** 通信中间件框架（transport）。
- **本版本：** 协程原生目标架构（草案）。根命名空间 `transport`；协程栈命名空间 `transport::coro`。
- **架构基线：** 全栈**协程原生**——并发/时序由 **AsyncTask 协程运行时**（boost.fiber）承担；传输抽象为**协程 await 式 `ITransport`**、具体实现薄包 coro socket（tcp/udp/串口）+ DDS 经桥实现同一抽象；交互模式由**各 node 自实现**（无独立 `InteractionEngine`/`InteractionPolicy`，关联键/帧类型判定内联进各 node）。
- **与实现的关系：** 本 SRS 是**目标需求**，驱动后续从 as-built v0.3.0 演进；差异见各章节「与当前实现的差异」注记与 §4.2。

### 1.2 概述

本软件把**传输**、**编解码**、**交互模式**解耦，并以**协程**为统一并发模型：

- **协程运行时** —— 单 fiber 调度线程（= Qt 事件循环线程），同时推进协程与 Qt 事件；请求-应答等交互写成线性的 `await`，**无线程池执行器**。
- **协程传输（`ITransport`）** —— 各介质抽象为协程 await 式 `ITransport`（`Open`/`Read`/`Write`/`Close`），具体实现薄包 AsyncTask 协程套接字（`corosocket`/`coroiodevice`/`corotcpserver`）；DDS 经 provider + listener→fiber 桥实现同一 `ITransport`。node 经 `ITransport` 介质无关。
- **编解码（ICodec）** —— 在收发边界把 `Message` ↔ 线缆字节（分帧 + 序列化 + 交互元数据），可插拔。
- **交互节点（node）** —— 每个 node（`ProtocolNode`/`DdsNode`）**自行实现**其所需交互模式（请求-应答/反馈/周期/发布-订阅等），关联/判别逻辑内联；节点是编程主入口，用户继承或组合获得通信能力。

**用途：** 本机进程间 + 跨网络（混合）通信。**非用途：** 不是消息代理/路由守护进程，不解释 payload 业务语义。

## 3. 需求

### 3.1 能力需求（RT_BASIC_ABILITY）

本软件应提供以下能力。每项按「功能需求 / 输入输出 / 行为过程描述 / 行为参数」四方面说明。公共约束：C++17、不抛异常、可失败操作返回标 `[[nodiscard]]` 的 `Result<T>` / `Status`（错误串前缀 `config:` / `frame:` / `codec:` / `conn:` / `timeout:` / `io:`）。

#### 3.1.1 协程运行时能力（RT_CORO_RUNTIME）

> **替代原「执行器与线程模型能力」。** 不再有 `IExecutor`/`ThreadExecutor` 抽象。

##### 3.1.1.1 功能需求

- 本能力应以 **AsyncTask 协程运行时**（boost.fiber）作为框架**唯一并发/时序模型**：宿主经 `Coro::installFiberApplication()` 在主线程安装本地 fiber 调度器并 `exec()`；该调度器**同时推进协程（fiber）与 Qt 事件**。
- 应提供协程原语的使用契约：`makeTask(fn)` 派生 fiber（默认 affinity 固定于当前=调度线程）；`Coro::Awaitable<T>`（`await_for(timeout) → Result<T,error_code>`、`resolve`）用于挂起/唤醒；`boost::this_fiber::sleep_for`/定时用于周期与超时。
- 应保证：所有传输 I/O、编解码、交互协程**运行于同一 fiber 调度线程**，协作式调度，**默认无锁**。

##### 3.1.1.2 输入输出

- **输入：** 宿主对 `installFiberApplication` / `exec` / `quit` 的调用；`makeTask` 的可调用体。
- **输出：** `exec()` 退出码；协程的 `Result<T>` 返回值。

##### 3.1.1.3 行为过程描述

宿主装运行时并进入 `exec()`；业务以 `makeTask` 派生协程；协程内以 `await`/`await_for` 挂起等待 I/O 或应答而**不阻塞线程**（其他协程与 Qt 事件照常推进）；`quit()` 触发安全退出（排空在途协程与事件）。

##### 3.1.1.4 行为参数

- **线程模型：** 单 fiber 调度线程 = Qt 事件循环线程；协作式、无抢占。
- **调用约束：** 所有 `await`/`await_for`/coro socket 操作**必须在固定于调度线程的 fiber 内**调用（`makeTask` 默认满足）；不得在裸非 fiber 线程或**共享 affinity 的 `.then` 续体**中调用（否则跨线程访问单线程状态）。
- **异常条件与异常下行为：** 不抛异常；协程内错误经 `Result` 上抛/返回；`quit` 期间新派生协程按运行时规则收敛。

#### 3.1.2 协程字节传输能力（RT_TRANSPORT）

> **抽象为协程 await 式 `ITransport`**（保留分层 / 可测 / 可换的价值），**具体实现薄包协程库的 coro socket**；node 对四介质介质无关。

##### 3.1.2.1 功能需求

- 本能力应把各介质字节收发抽象为**协程原生 `ITransport`**（await 式，方法在 fiber 内挂起，不阻塞线程）：
  - `Status Open()` —— 客户端 await 建立连接，返回 Success 即已连；
  - `Result<Datagram> Read()` —— 协程挂起直到收到数据 / 断开 / 错误；`Datagram = {bytes, from}`；
  - `Status Write(bytes)` / `Status Write(bytes, Endpoint)` —— await 写出；
  - `void Close()`。
- **具体实现薄包 coro socket：** `TcpTransport` → `corosocket`（`QTcpSocket`）；`UdpTransport` → `corosocket`（`QUdpSocket`，报文）；`SerialTransport` → `coroiodevice`（`QSerialPort`/`QIODevice`）；`DdsTransport`（`IDdsTransport : ITransport` + `Subscribe`/`Unsubscribe`）→ `IDdsProvider` + listener→fiber 桥（`Read()` await 桥 channel、`from`=topic；`Write(Endpoint::Topic)`→publish）。**DDS 亦实现同一抽象。**
- **接受器 `TcpServerTransport`（非 `ITransport`）：** `Result<std::shared_ptr<ITransport>> Accept()` —— 协程 await 下一连接（`corotcpserver`），返回一条已连 `TcpTransport`。
- **回调收敛：** 不再有 `OnConnect`/`OnDisconnect`——连接成功 = `Open()` 返回 Success；断开 = `Read()` 返回 `conn:` 错误。
- 应保留中立寻址值类型 `Endpoint`（`Default` / `Net(ip,port)` / `Topic(name)`）。

##### 3.1.2.2 输入输出

- **输入：** 各介质配置（host/port、绑定地址、波特率、`DdsConfig` 等）；`Write` 的字节 `std::vector<uint8_t>` + 可选 `Endpoint`。
- **输出：** `Open` / `Write` 返回 `Status`；`Read()` 返回 `Result<Datagram>`（`{bytes, from}`，或 `conn:` / `io:` 错误）；`Accept()` 返回 `Result<std::shared_ptr<ITransport>>`。

##### 3.1.2.3 行为过程描述

1. node 持 `std::shared_ptr<ITransport>`（介质无关），`Open()`（或经 `Accept()` 得已连接实例）。
2. node 派生**读-分发协程**：`for(;;){ auto r = t->Read(); if(!r){ 终结全部挂起(conn:); break; } codec.Decode(r.bytes) → 内联关联 → resolve 请求 Awaitable / 交钩子 }`。
3. 发：请求协程 `t->Write(encode(...))`，随后 `await_for(pending[key], timeout)` 等应答。

##### 3.1.2.4 行为参数

- **Read 报文 / 流式语义（接口统一、语义随介质）：** UDP/DDS **一次 `Read()` 一个完整 datagram/sample**（保边界，`from` 可变——来源 ip:port / topic）；TCP/串口 **一次 `Read()` 一段任意字节切片**（无边界，`from` 恒为该连接对端）。**传输层不切帧**——拼帧归上层 codec（UDP 配无状态 `SystemDatagramCodec` 一报文一帧；TCP/串口配有状态 `SystemCodec` 滚动缓冲切帧）。
- **线程与时序：** 所有 `ITransport` 方法在 fiber 调度线程调用（须在 fiber 内）；DDS 样本经桥有序投入调度线程。
- **异常条件与异常下行为：** 连接失败 / 超时 → `Open()` / `await_for` 返回 `conn:` / `timeout:`；对端断开 → `Read()` 返回 `conn:`（读协程据此终结在途请求）；配置非法 → `config:`；UDP 单包 I/O 错误不致命、可继续 `Read()`。

#### 3.1.3 线缆编解码能力（RT_CODEC）

##### 3.1.3.1 功能需求

- 本能力应在收发边界把 `Message` ↔ 线缆字节，抽象为 `ICodec`：`Encode(const Message&) → Result<std::vector<uint8_t>>`；`Decode(const uint8_t*, size_t) → Result<std::vector<Message>>`。
- 应提供内置 codec：`SystemCodec`（外部协议帧，有状态流式，配 TCP/串口）、`SystemDatagramCodec`（同帧无状态报文版，配 UDP）、`DdsCodec`（带交互元数据的 DDS 格式）、`LengthFieldCodec`、`DatagramCodec`。

##### 3.1.3.2 输入输出

- **输入：** `Encode` 收 `const Message&`；`Decode` 收字节切片；`SystemCodec` 构造注入 `CrcFn`。
- **输出：** 字节 / `0..N` 条 `Message`。

##### 3.1.3.3 行为过程描述

编码序列化头部 + payload + CRC；解码（有状态）追加滚动缓冲、扫同步头、校验、切帧、resync 坏帧；解码（无状态）整段单帧、残留丢弃。节点读协程把 `ITransport::Read()` 读到的字节喂 `Decode`。

##### 3.1.3.4 行为参数

- **有状态性：** 有状态 codec 由单一（调度）线程喂；无状态 codec 并发安全。
- **帧长约束：** `SystemCodec` 帧 `frm_len = 2 + payload_len ≤ 65535`，超限编码报 `frame:`。
- **异常下行为：** 坏帧头/越界 → `frame:`；序列化错 → `codec:`；流式坏帧 resync 继续；残帧丢弃。

#### 3.1.4 外部协议交互节点能力（RT_PROTONODE）

> **各 node 自实现交互模式；关联键/帧判定内联（无独立引擎/策略）。**

##### 3.1.4.1 功能需求

- 本能力应提供 `ProtocolNode`，**自行实现**面向外部系统协议的交互模式：`noresponse` / `needresponse`（等 RESPONSE）/ `withfeedback`（等 RESULT）/ `needfeedback`（RESPONSE → RESULT → 自动回 RESPONSE ack）/ `repeating`（定时发 STATE，可停）；发送方法首参 `uint16_t cmd`（= `message_id` 命令码）。
- 应自实现：收发双角色（收 COMMAND/STATE → 处理并可回应）、周期心跳、`repeating` 取最新状态、UDP 1:多寻址。
- **关联/判别内联**：节点内一个**读-分发协程**读 `ITransport`（`t->Read()`）→ `codec.Decode` → 按**内联的 `(session_id, message_id)` 匹配键**把应答 `resolve` 给等待中的请求 `Awaitable`；无独立 `InteractionEngine`/`InteractionPolicy`。

##### 3.1.4.2 输入输出

- **输入：** 协议配置（`protocol_id`、`reply_to_source`、`heartbeat_interval_ms`、`max_retries`）+ 注入的 `ITransport`；`cmd` + payload + 交互模式 + 可选 `Endpoint`。
- **输出：** 各模式应答（协程 `Result<Message>` / 回调）；入站 COMMAND/STATE/HEARTBEAT 经节点钩子交付。

##### 3.1.4.3 行为过程描述

1. `Start` 经 `ITransport::Open()` 建立连接（或经 `Accept()` 得已连实例），派生**读-分发协程**与（若配）**心跳协程**。
2. 请求：请求协程 `NewCorrelation`（滚 `session_id`、盖 `protocol_id`，内联）→ 登记 `Awaitable` 于节点挂起表（键=`(session_id, message_id)`）→ `t->Write(encode)` → `await_for(timeout)`。
3. 读-分发协程：`auto r = t->Read()` → `codec.Decode(r.bytes)` → 按内联匹配键命中挂起表则 `resolve`（终结帧终结、中间帧按模式处理），未命中 → COMMAND/STATE/HEARTBEAT 交节点钩子。
4. `needfeedback` 收 RESULT 后自动回 RESPONSE ack；`repeating` 由周期协程 `sleep_for` 循环发 STATE。

##### 3.1.4.4 行为参数

- **超时/重发：** `await_for(timeout)` 超时重发 COMMAND ≤ `max_retries`（默认 3）后失败 `timeout:`；「首帧停重发」由节点内联。
- **并发约束：** 未决请求受 `(session_id, message_id)` 键空间约束（`session_id` 滚动 0–255 → 同命令并发 ≤ 256）。
- **UDP 1:多：** `reply_to_source=true` 回送入站来源 ip:port；发送带可选 `Endpoint::Net`；匹配仅按 `(session_id, message_id)`，不校验来源。
- **线程约束：** 请求方法须在 fiber 内调用（RT_CORO_RUNTIME 3.1.1.4）。
- **异常下行为：** 断连 → 读协程终结全部挂起（`conn:`）；`state_fn` 须非阻塞/不抛，空 → 不启动。

#### 3.1.5 DDS 交互节点能力（RT_DDSNODE）

> **协程化的 DDS 节点；自实现交互模式；关联内联。**

##### 3.1.5.1 功能需求

- 本能力应提供 `DdsNode`，基于 `IDdsProvider` + listener→fiber 桥，**自行实现**：多 topic 发布/订阅、多路请求-应答（经 `reply_to` 精确回送发起方 inbox）、周期发布。
- **关联内联**：以 `correlation_id` 为匹配键、`MessageKind` 为判别符，节点内联登记/匹配挂起（无独立引擎/策略）。

##### 3.1.5.2 输入输出

- **输入：** `DdsConfig`；发布 `Send(msg, Endpoint::Topic(t))`；请求 `Request(..., Endpoint::Topic(req_topic))`；`Subscribe`/`Unsubscribe`；周期 `StartPublishing`/`UpdatePublishing`/`StopPublishing`。
- **输出：** 发布/订阅/请求的 `Result`/应答；入站样本经节点钩子交付。

##### 3.1.5.3 行为过程描述

`Start`/`Open()` 经 `DdsTransport`（`IDdsTransport : ITransport`）自动订阅本节点 inbox topic 并派生**读-分发协程**（`t->Read()`，内部 await listener→fiber 桥取样本）；发布经 `t->Write(msg, Endpoint::Topic)`；请求携带自身 inbox topic 入 `reply_to`，读-分发协程按 `correlation_id` 命中挂起表则 `resolve`；服务端据 `reply_to` 精确回送。

##### 3.1.5.4 行为参数

- **桥有序性：** provider listener 线程样本经协程 channel 桥有序投入调度线程；同 topic 有序、跨 topic 并发在桥入口收敛为调度线程串行。
- **异常下行为：** provider 未注册 → `config:`；DDS 收 `Endpoint::Net` → `config:`；空周期工厂 → 不启动。

#### 3.1.6 错误处理能力（RT_ERROR）

##### 3.1.6.1 功能需求

框架不抛异常；可失败操作返回标 `[[nodiscard]]` 的 `Result<T>` / `Status`，错误串前缀分类 `timeout:` / `conn:` / `codec:` / `frame:` / `io:` / `config:`。

##### 3.1.6.2 输入输出

- **输入：** 各操作失败条件。**输出：** `Result<T>::Fail(msg)` / `Success(v)`（`msg` 带前缀）。

##### 3.1.6.3 行为过程描述

失败就近以带前缀 `Result`/`Status` 返回或经协程结果上抛；消费方按前缀处置。

##### 3.1.6.4 行为参数

- **前缀语义：** `config:`（未开/用错种类/配置非法）、`frame:`（分帧/越界/同步）、`codec:`（序列化）、`conn:`（断开/关闭/被拒）、`timeout:`（请求/重发耗尽）、`io:`（底层 I/O）。
- **异常下行为：** 不崩溃；坏帧 resync/丢批继续；断连终结挂起。

#### 3.1.7 交互可观测能力（RT_TRACE）

##### 3.1.7.1 功能需求

本能力应提供可插拔结构化 trace：层中立 `ITraceSink` 注入各 node，观测交互全流程（连接/收发/分发/超时/重发/周期/关闭）；内置 `OstreamTraceSink`（→ ostream）/ `CapturingTraceSink`（深拷贝，测试用）。

##### 3.1.7.2 输入输出

- **输入：** `node->SetTrace(sink)`；节点咽喉点产生 `TraceEvent`。
- **输出：** `TraceEvent`（零分配视图：`TraceLevel` 5 级 + category + `string_view`/`int` 字段）交付 sink。

##### 3.1.7.3 行为过程描述

节点在咽喉点产生事件交 sink；观测-only，不改控制流/字节流/错误模型。

##### 3.1.7.4 行为参数

- **近零开销：** 无 sink 时单分支、字节流逐字不变。
- **线程：** 单调度线程内产生；sink 若跨线程留存须自身线程安全。

### 3.2 外部接口需求（RT_INTERFACE）

#### 3.2.1 接口标识和接口图

外部接口分两类：① **库编程接口**（宿主经 `include/transport/*` + 协程运行时链接调用）；② **通信介质接口**（tcp/udp/串口经协程 `ITransport`（coro socket 实现）、DDS 经 provider + 桥 与外部端在线缆上交互）。

```
        宿主应用（在 makeTask 协程内调用）
           │  RT_IF_API：include/transport/* + AsyncTask 运行时
           ▼
   ┌──────────────────────────────────────┐
   │  transport 库（协程原生）              │
   │  node（自实现交互模式，关联内联）      │
   │  ICodec                               │
   │  ITransport（coro socket 实现）/ DDS 桥 │
   └───┬────────┬────────┬────────┬────────┘
       │TCP     │UDP     │串口     │DDS(provider+桥)
   (RT_IF_TCP)(RT_IF_UDP)(RT_IF_SERIAL)(RT_IF_DDS)
       ▼        ▼        ▼         ▼
    外部通信端 / 网络 / 设备 / DDS 域
       └── 线缆帧：RT_IF_SYSFRAME（外部系统协议帧） ──┘
```

#### 3.2.2 库编程接口（RT_IF_API）

- **形式：** C++ 头文件 API（`include/transport/*`）+ AsyncTask 协程运行时头（`installFiberApplication`/`makeTask`/`Awaitable`/coro socket）。
- **主 API：** 各协程 node（`ProtocolNode`/`DdsNode`）+ 其交互方法；宿主须在 `makeTask` 协程内使用。
- **传输/编解码扩展：** `ITransport`（coro socket 实现）/ `ICodec` 实现 / `IDdsProvider` / `ITraceSink`。
- **共享数据类型：** `Message` / `Result` / `Status` / `Endpoint`。

#### 3.2.3 TCP 网络接口（RT_IF_TCP）

- **形式：** TCP/IP 流式套接字，经 `corosocket`（`QTcpSocket`）/ `corotcpserver`（`QTcpServer`）协程访问。
- **线缆语义：** 字节流；帧边界由上层 ICodec。**参数：** 连接超时（`await_for`）、服务端监听 `bind_addr:port`。

#### 3.2.4 UDP 网络接口（RT_IF_UDP）

- **形式：** UDP 数据报套接字，经 `corosocket`（`QUdpSocket`）协程访问。
- **线缆语义：** 报文边界，一 datagram 一次；`from` 含 `"ip:port"`。**参数：** 绑定、默认目的地、运行期 `Endpoint::Net`。

#### 3.2.5 串口接口（RT_IF_SERIAL）

- **形式：** 串行端口，经 `coroiodevice`（`QSerialPort`/`QIODevice`）协程访问。
- **线缆语义：** 字节流；切帧归上层。**参数：** 设备路径/波特率/数据位/停止位/校验；非法 → `config:`。

#### 3.2.6 DDS 接口（RT_IF_DDS）

- **形式：** DDS 发布-订阅（`IDdsProvider` 适配 Fast DDS/Fake），样本经 listener→fiber 桥进入协程；一实例 = 一 `DomainParticipant`。
- **线缆语义：** 每 sample 一条完整消息（`DdsCodec`）。**参数：** `DdsConfig = {domain_id, default_topic, provider, qos}`；多路 req-resp 依赖 `reply_to`，对端须为同框架 `DdsNode`。

#### 3.2.7 外部协议帧接口（RT_IF_SYSFRAME）

- **形式：** 外部系统协议帧（`SystemCodec`/`SystemDatagramCodec`），跑于 TCP/串口（流式）或 UDP（报文）。
- **线缆格式（小端）：** `[head_flag:4=AA BB CC DD][frm_type:1][protocol_id:1][session_id:1][reserve:4=0][crc:2 LE][frm_len:2 LE][frm_body: message_id:2 LE | payload]`（头 15 字节；`frm_len ≤ 65535`）。
- **参数与约束：** `frm_type`（COMMAND/RESPONSE/RESULT/STATE/HEARTBEAT/UNKNOWN）；`protocol_id` 区分外部系统；CRC 经 `CrcFn` 注入。**`frm_type` 真值与 CRC 算法为外部常量**，占位 + 注入预留，接入前替换、两端一致。

### 3.3 内部接口需求（RT_IN_INTERFACE）

> 相较原（异步栈）文：**删除** `IExecutor`（执行器）与 `InteractionPolicy`（策略）内部接口——并发交给协程运行时、交互与关联内联进各 node；**保留** `ITransport` 缝但改为**协程 await 式**（不再回调）；**新增** DDS 桥接口（现为 `DdsTransport` 内部）。

#### 3.3.1 传输缝 `ITransport`（RT_INIF_TRANSPORT）

`ITransport` 应保留为**公共、干净、稳定的纯虚契约**——是分层、可测（`FakeTransport` 替真实 socket）、可换（换介质只换注入的 transport）的支点；但接口由回调式改为**协程 await 式**：`Status Open()` / `Result<Datagram> Read()`（协程挂起，`Datagram = {bytes, from}`）/ `Status Write(bytes[, Endpoint])` / `void Close()`。`OnConnect`/`OnDisconnect` **收敛**进 `Open()` 返回与 `Read()` 的 `conn:` 错误。具体实现薄包协程库 coro socket（`corosocket`/`coroiodevice`/`corotcpserver`），DDS 实现经 provider + 桥。**不得回退为回调式 `OnBytes`。** 报文/流式语义见 RT_TRANSPORT 3.1.2.4，切帧归上层 codec。

#### 3.3.2 编解码缝 `ICodec`（RT_INIF_CODEC）

`ICodec` 应对各 node 可插拔替换（线缆格式与交互正交）。有状态实现单（调度）线程喂，无状态实现并发 `Decode` 安全。

#### 3.3.3 DDS provider 缝 `IDdsProvider`（RT_INIF_DDSPROVIDER）

`IDdsProvider` 应把 DDS 底层库适配为可换（Fast DDS / `FakeDdsProvider`），经 `DdsProviderRegistry` 按名注册；DDS 业务须零 FastDDS 依赖即可用 `FakeDdsProvider` 全测。

#### 3.3.4 DDS 协程桥 `IDds→Fiber Bridge`（RT_INIF_BRIDGE）

DDS provider listener 线程到达的样本应经一个**线程安全的协程 channel 桥**投入 fiber 调度线程，供 `DdsTransport::Read()` `await` 消费（桥现为 `DdsTransport` 的内部实现）。桥应保证：样本不丢 / 有序入队；桥出口在调度线程串行；`Close` 时唤醒并收敛等待者。此桥是「provider（他线程）↔ 协程世界（调度线程）」的唯一交接点。

#### 3.3.5 可观测缝 `ITraceSink`（RT_INIF_TRACE）

`ITraceSink` 应层中立、观测-only、近零开销，注入各 node；跨线程留存的 sink 实现须线程安全。

### 3.4 内部数据需求（RT_IN_DATA）

#### 3.4.1 消息模型 `Message`（RT_DATA_MSG）

`Message` 应承载 payload + 交互元数据（`kind`/`correlation_id`/`topic`/`source`/`reply_to`，DDS 路径）+ 外部协议字段（`frm_type`/`protocol_id`/`session_id`/`message_id`）。各 node 直接读写这些字段做内联关联（无策略层）。

#### 3.4.2 结果类型 `Result<T>` / `Status`（RT_DATA_RESULT）

不抛异常的「值或错误」载体，标 `[[nodiscard]]`，错误串前缀分类（RT_ERROR）。注：协程层另有 `Coro::Result<T,error_code>`（`await_for` 返回），node 应把其转为框架 `Result`（超时→`timeout:`、断开→`conn:`）。

#### 3.4.3 寻址类型 `Endpoint`（RT_DATA_ENDPOINT）

中立寻址值类型（`kDefault`/`kNet`/`kTopic`），零第三方依赖，与 `Message.topic`/`source` 对称。

#### 3.4.4 配置数据（RT_DATA_CONFIG）

各传输/节点配置为纯数据结构，校验严格（非法 → `config:`）。

#### 3.4.5 外部协议帧数据（RT_DATA_FRAME）

布局见 RT_IF_SYSFRAME；`frm_type` 真值与 CRC 算法为待注入外部常量。

### 3.5 设计和实现约束（RT_DESIGN）

- **语言/标准：** C++17；不抛异常，统一 `Result<T>`/`Status`（`[[nodiscard]]`）；Google 风格。
- **并发模型（强约束）：** **AsyncTask 协程运行时为唯一并发模型**——单 fiber 调度线程（= Qt 事件循环线程）；**不引入线程池执行器（`IExecutor`）**。所有 I/O/编解码/交互协程同线程协作式、默认无锁。DDS provider 他线程样本仅经 RT_INIF_BRIDGE 交接。
- **传输约束：** 各介质抽象为**协程 await 式 `ITransport`**（`Open`/`Read`/`Write`/`Close`），**具体实现薄包 AsyncTask coro socket**（`corosocket`/`coroiodevice`/`corotcpserver`）；DDS 经 provider + listener→fiber 桥实现同一 `ITransport`。**不得回退为回调式 `OnBytes`。** node 经 `ITransport` 介质无关。
- **交互约束：** **不设独立 `InteractionEngine`/`InteractionPolicy` 抽象**；各 node 自实现所需交互模式，关联键/帧类型判定内联。共享仅限轻量协程模式辅助（读-分发循环、请求-await channel），不得回归单体引擎。
- **构建：** CMake；AsyncTask（git 子模块 `third_party/AsyncTask`，`ASYNC_HAS_QTCORE` + AUTOMOC）+ 已编译 boost `fiber/context/thread/chrono`（`ASYNCTASK_DIR`/`BOOST_LOCAL_ROOT`）；Qt5（Core/Network/SerialPort，coro socket 底层）；nlohmann/json、GoogleTest vendored。
- **平台：** Linux。**对象持有：** 节点/协程句柄以 `std::shared_ptr` 持有，注意 fiber 生命周期。
- **可扩展/可替换：** codec 经 `ICodec` 换；DDS 库经 `IDdsProvider` 换；可观测后端经 `ITraceSink` 换。

### 3.6 其他需求（RT_OTHER）

- **可测性：** node 用可编程 Fake coro 传输/Fake provider + fiber 测试夹具（`installFiberApplication` + `makeTask` 内跑断言）端到端可测；DDS 用 `FakeDdsProvider`；串口回环用 `socat` pty（不可用则 `GTEST_SKIP`）。
- **可选依赖降级：** Fast DDS 未装跳过真实互通（用 `FakeDdsProvider` 全测）。
- **迁移：** 本目标架构相对 as-built v0.3.0 为演进：去 `IExecutor`/`InteractionEngine`/`InteractionPolicy`、`ITransport` 由回调式改为协程 await 式（coro socket 实现）、DDS 加桥。演进应分期、保持每期可测。

## 4. 注释

### 4.1 术语与缩略语

| 术语 | 含义 |
|---|---|
| 协程运行时 | AsyncTask/boost.fiber 提供的 fiber 调度（`installFiberApplication`/`exec`），单调度线程 = Qt 事件循环线程 |
| fiber | 协作式协程；本框架的并发/调度单位（`makeTask` 派生） |
| ITransport | 协程 await 式字节管道抽象（`Open`/`Read`/`Write`/`Close`，`Read`→`{bytes, from}`）；具体实现薄包 coro socket，node 经它介质无关 |
| coro socket | AsyncTask 封装的协程套接字/设备：`corosocket`（QAbstractSocket，TCP/UDP）、`coroiodevice`（QIODevice，串口）、`corotcpserver`（accept）——为 `ITransport` 具体实现底层 |
| Awaitable | 协程等待器（`Coro::Awaitable`），`await_for(timeout)` 挂起当前 fiber、`resolve` 唤醒 |
| listener→fiber 桥 | DDS provider 他线程样本进入协程世界的线程安全 channel 交接（RT_INIF_BRIDGE） |
| node（节点） | 交互编程主入口（`ProtocolNode`/`DdsNode`），**自实现**交互模式、内联关联 |
| ICodec | 线缆格式扩展点：`Encode(Message)→bytes` / `Decode(bytes)→0..N Message` |
| Endpoint | 中立寻址目的地值类型（`Default`/`Net`/`Topic`） |
| Message | 一条消息的数据模型（payload + 交互元数据 + 协议字段） |
| provider | DDS 底层库的抽象适配（`IDdsProvider`），如 Fast DDS / `FakeDdsProvider` |

### 4.2 与 as-built v0.3.0 的差异（追溯）

| 方面 | as-built v0.3.0 | 本目标架构 |
|---|---|---|
| 并发/线程 | `IExecutor` + `ThreadExecutor`（单 worker）；异步栈 | **AsyncTask 协程运行时**（单 fiber 调度线程），去执行器 |
| tcp/udp/串口传输 | QtNetwork 回调式 `ITransport`（`OnBytes`） | **协程 await 式 `ITransport`**（`Read`/`Write`，薄包 coro socket） |
| DDS | provider + 回调，异步引擎 | provider + **listener→fiber 桥**，协程节点 |
| 交互机制 | 共享 `InteractionEngine` + 声明式 `InteractionPolicy` | **各 node 自实现**，关联键/帧判定**内联**，无独立引擎/策略 |
| 协程栈现状 | 已有 `coro::InteractionEngine`（复用 `ITransport` 桥），但仍是「引擎」形态 | 去引擎，node 经协程 `ITransport`（coro socket 实现）写协程 |

> v0.3.0 已完成传输 QtNetwork 化与一个复用 `ITransport` 的协程引擎（PR #12/#13）；本目标架构进一步：去执行器与引擎抽象、`ITransport` 改协程 await 式（coro socket 实现）、DDS 加桥。属后续演进，非当前实现。

### 4.3 范围外 / 后续

- 迁移分期计划（含每期可测边界）；`corosocket` 对 UDP 报文语义的适配确认；DDS 桥的背压与关闭时序细化。
- `ProtocolNode` 的 `noresponsewithcheck`、多外部系统路由表、QoS 细配、payload>65533 分帧、配置驱动工厂。

### 4.4 标识符前缀说明

章节标识符统一用前缀 `RT`（需求-Transport）。如需对齐其他标识规范，可全局替换前缀，章节层级与语义不变。
