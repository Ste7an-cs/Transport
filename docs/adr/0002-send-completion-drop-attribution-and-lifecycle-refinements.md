# ADR-0002：发送完成语义、丢弃归因与生命周期细化

**状态：** Accepted（草案 / 目标架构，尚未实现）
**日期：** 2026-07-22
**关联：** `docs/需求规格说明书-协程原生.md`（SRS v3，本轮落点）；`docs/adr/0001-coroutine-native-interaction-architecture.md`（本 ADR 细化其 D4/D5/D13/D16 与关闭其两项"尚未解决"）；`third_party/AsyncTask/coro/await/corosocket.hpp`（可行性核对依据）。

## 背景（Context）

ADR-0001 确立协程原生总纲后，一轮针对 SRS v2 的需求 grilling 暴露若干可验收性缺口：并发发送排序留空（旧 TBD-002）、发送侧缺背压与内存上界、无连接介质的判活层次未定、DDS 交接容量/溢出留空（旧 TBD-006 的一半）、业务队列字节范围未定（TBD-006 另一半）、"框架丢失=0"不可审计。本 ADR 记录这些决策及其代码可行性核对结论。

## 决策（Decision）

- **D1（发送排序）：** 并发发送排序 = **节点执行域到达顺序**。单 fiber 程序序必被保持；跨 fiber 并发发送在节点所属执行域内串行化并取得某个一致全序，但不保证可由调用方墙钟时序预测。否决"跨调用方全局 FIFO"作为验收条件。**关闭 ADR-0001 遗留项"多线程/多 fiber 并发发送的跨调用方顺序"与 SRS TBD-002。** 落点 RT_TRANSPORT_007。

- **D2（发送完成语义与背压）：** 一次发送以"该帧字节全部离开框架/Qt 用户态发送缓冲、进入操作系统发送缓冲"为完成判据（非"对端已收"）。由此每连接用户态写缓冲至多驻留一个在写帧，背压经协程 `await` 传导回发起方。**否决 fire-and-forget**（写入即返回、无界缓冲吸收）——会致 Qt 默认无界写缓冲增长、背压消失、"发送成功"语义失真、部分写失败无法回传发起方；若未来需要更高吞吐，应以"有界发送缓冲阈值背压"作为独立能力评审。落点新增 RT_TRANSPORT_008、3.1.2.4。

- **D3（判活层次）：** 无连接介质（UDP、串口、DDS）的链路判活归**协议/交互层**（心跳 + 超时；DDS 另可用 Liveliness/Deadline QoS）。传输层不得为无连接介质构造伪连接状态，只暴露 I/O 事实（最近收发时间戳、收发计数、单操作错误），供协议层形成健康结论。落点 RT_NODE_006。

- **D3′（非重连节点生命周期）：** 连接状态机与自动重连为 TCP 客户端专属语义，且连接状态是 TCP 客户端在 `Running` 内的**子状态**，非与节点生命周期对等的第二生命周期。其余节点（TCP 服务端已接受连接、UDP、串口、DDS）无 `Reconnecting`，其底层连接/设备致命错误使节点 `Closing→Closed`（连接生命等同节点生命）。**串口断开的过渡默认由此确定**（致命→Closed，复用靠宿主重建），TBD-005 降级为"是否新增串口自动重连能力"。落点 RT_LIFECYCLE_002。

- **D4（DDS 交接容量与溢出）：** DDS provider 交接边界使用有界队列，非阻塞地把样本交入节点执行域；满时**丢最新样本（tail-drop）** 并记 `ResourceExhausted`/丢弃计数/Trace，与业务队列溢出语义一致。默认容量 **1024 样本且 16 MiB、独立可配**（事件数 1～65536）。本地已丢样本不得宣称由 DDS Reliable 自动恢复。**关闭 ADR-0001 遗留项"DDS provider 本地交接容量与溢出策略"及 SRS TBD-006 的 DDS 部分；细化 ADR-0001 D4。** 落点 RT_NODE_007、3.1.9.4。

- **D5（业务队列字节范围）：** 业务队列字节上限可配范围 **64 KiB～256 MiB（每节点）**，默认 16 MiB。框架不跨节点核算聚合内存，宿主须保证 Σ(各节点业务队列 + DDS 交接队列上限) 落在 RSS 预算（≤1 GiB）内。**关闭 TBD-006 剩余部分。** 落点 3.1.5.4。

- **D6（完整性可验证化）：** "框架导致丢失/重复 = 0"定义为可验证判据——无外部故障且负载 ≤ 配置容量时，每条已接受入站业务消息恰好一次完成、每个已发送帧恰好一次上线、损失类计数器全 0。**每一次本地丢弃/重复抑制归因到恰好一个命名且计数的原因**（业务队列溢出、DDS 交接溢出、坏帧、迟到/重复/无匹配响应、关闭丢弃、连接代际隔离丢弃），Σ(命名原因计数) = 总丢弃，无静默丢失；迟到/重复/坏帧属正确过滤而非丢失。落点 3.6.2、3.6.3、3.4.4。

**事实核对（F1，corosocket.hpp）：** D1/D2 可用现有原语实现，**不改 AsyncTask、不改 corosocket、不向用户暴露 corosocket**。`CoroAbstractSocket` 只提供读/等信号原语（无 `write`）；发送刷完循环由 transport 层组合裸 `QAbstractSocket::write()` + `while(bytesToWrite()>0) await(waitForBytesWritten())`（`while` 守卫强制，否则空写会挂）。连接/读/发送超时用 AsyncTask `await_for`；关闭取消经撕 socket 触发信号或 fibertask `cancel()`。可选 `writeAll(frame)` 仅为一次性 connect 循环的效率优化，正确性不需要。

## 影响（Consequences）

- **正面：** 发送侧内存有明确上界且背压天然（无需新增发送队列配置项）；"丢失=0"从口号变为可断言测试；判活层次划清，避免给无连接介质造伪状态；DDS 交接与业务队列共用一套溢出语义，验收模型统一。
- **代价/风险：** await-每帧-刷完放弃了多帧流水线，峰值吞吐上限受单帧 drain 影响（按 100 Hz/1 KiB 负载模型非瓶颈）；聚合内存正确性依赖宿主自律（框架不强制），需在验收清单提示；命名丢弃原因需在实现中逐点埋计数器，遗漏即静默丢失。
- **可逆性：** D2 的"发送完成判据"是行为契约，较难改（改动影响请求超时归因、取消语义、部分写失败回传）；D4/D5 的默认值可逆（调参）；D1 的排序保证一旦公开即契约。
- **SRS 落点：** RT_TRANSPORT_007/008、RT_NODE_006/007、RT_LIFECYCLE_002、§3.1.5.4、§3.1.9.4、§3.4.4、§3.6.2、§3.6.3；TBD-002、TBD-006 关闭，TBD-005 重述。

## 尚未解决

- 有界发送缓冲阈值背压（提高吞吐的可选能力）——若未来需要再作独立评审。
- 串口自动重连能力及真实硬件验收条件（TBD-005，过渡默认已定）。
- 业务队列/DDS 交接字节上限与 RSS 预算的聚合核算是否需框架侧辅助工具——当前归宿主。
- "socket 的 QThread ↔ 节点执行域"绑定机制——属 RT_IN_INTERFACE_005 的 SDD 职责。
