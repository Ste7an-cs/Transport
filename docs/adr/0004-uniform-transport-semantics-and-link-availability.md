# ADR-0004：传输语义统一、链路可用性上移与发送完成语义撤销

> **注（2026-08-19）**：本 ADR 的 **D1（终止表达）已由 ADR-0007 D4 改写**、**D2 的观测面（`LastSendTime`/`LastReceiveTime`）已由 ADR-0008 D1 删除**；其撤销「发送完成语义」的结论则被 ADR-0008 **D4 推向彻底的 fire-and-forget**。其余决策不受影响。

**状态：** Accepted
**日期：** 2026-08-06
**关联：** `docs/需求规格说明书-协程原生.md`（本 ADR 落点：RT_TRANSPORT_008/009、RT_REQUEST 总超时缺省、RT_TCP_RECONNECT_002/005、RT_IN_INTERFACE_002）；ADR-0002（**本 ADR 撤销其 D2、重划其 D3′**）；ADR-0003（D11 连接管理分层——本 ADR 改其观察面部分）。

## 背景（Context）

一轮针对"生命周期设计过于复杂、尤以 TCP 客户端为甚"的需求层 grilling 暴露出：复杂度的真正来源**不是**分层（`TcpClientTransport` 外层包 `TcpTransport` 内层），而是**交互层被迫感知连接管理**：

- `ProtocolNode::Start` 用 `dynamic_cast<IConnectionObservable*>` 探测传输能力，分出两条启动路径；
- 探测命中则额外起一条 reactor 协程订阅连接状态跃迁，据"曾 Connected 且现非 Connected"的下降沿做**连接代际隔离**（批量终结在途请求 + 清空旧代际排队业务）；
- 由此牵出 `reactor_cancellation_`、`reactor_done_`、finalizer 追加汇合点等一串仅为该特例存在的同步件。

量化：`TcpTransport` 397 行（已连接 socket 上的收发），`TcpClientTransport` 824 行——多出的部分是连接状态机、退避、代际、观察面与运行时重配置，**合并两层并不能消除它们**，反而要复制收发逻辑。

同时确认：`ITransport::Read` 的终止错误在各介质间语义不一（UDP/串口致命返 `kConnection`/`kIo`，而 TCP 客户端断链透明跨越），交互层无法用同一段读循环处理三种介质。

## 决策（Decision）

- **D1（读取终止语义单一化 + 重连完全透明）：** `Read` 的失败中仅 `kClosed` 表示**传输终结**（我方关闭，或不具重连能力的传输发生底层致命错误），调用方停止读取；其余失败均为可继续的瞬时错误。**具备自动重连的传输在内部透明处理链路中断**——`Read` 在重连期间挂起、重连后于新链路继续交付，**不向调用方暴露链路中断事件**。不具重连能力的介质（UDP、串口、已接受的 TCP 连接）致命错误由 `kConnection`/`kIo` 改返 `kClosed`。`kConnection` 此后仅存于**写路径**（链路不可用时发送立即失败，RT_TCP_RECONNECT_003）。落点 RT_TRANSPORT_008（重新定义）。
  取舍记录：曾设计为二义（`kConnection` = 链路断开、调用方续读），目的是让交互层在断链时重置编解码器；D4 撤销后交互层在断链时**无任何动作可做**，该信号随之失去用途，故收敛为单一终止语义。

- **D2（链路可用性上移基类，重划 ADR-0002 D3′）：** 在 `ITransport` 基类增加**链路可用性**查询，所有介质同形作答（具连接管理者反映其连接状态；无连接/单设备介质以"链路是否可用"作答）。**取消 `IConnectionObservable` 可选接口与交互层的 `dynamic_cast` 探测。**
  ADR-0002 **D3′** 原文"连接概念不下沉纯字节管道"按此重划边界：D3′ 真正要挡的是**连接管理**（状态机、退避、重连策略、代际推进）下沉；而**当前链路可用性**是与 `LastSendTime`/`LastReceiveTime`/`LastError` 同类的 **I/O 事实**（每种介质都答得出、不含策略），可入基类。连接管理本身仍只在 `TcpClientTransport` 内部。落点 RT_TRANSPORT_009、RT_IN_INTERFACE_002。

- **D3（撤销连接代际隔离）：** 断链时交互层**不再**批量终结在途请求、不再清空旧链路排队业务。在途请求改由各自总超时、调用方取消或节点关闭终结。**"代际"概念自交互层完全消失**（`PendingTable` 本就无代际字段）。
  正确性依据：旧链路 socket 已关闭，其字节不会投递到新链路；在途请求的关联标识在终结前不释放，新请求取不到同一关联键——RT_REQUEST_004 的"旧代际响应不得完成新请求"由**物理事实**保证，无需框架动作。
  代价：断链后在途请求至多等一个总超时才失败。故 **RT_REQUEST 增设总超时缺省值为强制项**（节点不得接受"永不超时"的请求），以维持 RT_REQUEST_003"每个请求恰好终结一次"。落点 RT_TCP_RECONNECT_002（改写）。
  连带：命名丢弃原因由七项减为六项（`连接代际隔离丢弃` 不再产生）。

- **D4（不引入编解码器重置——已撤销）：** 曾拟为 `ICodec` 增加重置操作以清断链残留。**否决**：接口负担（公共扩展点的破坏性变更、所有实现须跟进）大于收益，且错帧已有检出与恢复手段——半帧残尾与新链路首字节拼接产生的错帧由编解码器既有的校验与重同步处置（报坏帧、计入坏帧计数后恢复）。该情形在代际隔离时代同样存在（旧设计从未清过滚动缓冲），本 ADR 明确将其记为**已知且被接受的行为**而非缺陷。落点 §3.1.2.4 透明重连代价说明。

- **D5（撤销发送完成语义与协程背压，撤销 ADR-0002 D2）：** 删除"一次发送须在帧字节全部进入操作系统发送缓冲后才报成功、背压经协程等待传导"的要求。发送成功此后仅表示**该帧已交付下层发送通路**。
  **保留** RT_TRANSPORT_004 的并发写串行化（单帧字节不得与另一帧交错）——它与完成语义是两件事，串行化是其实现手段，不随 D5 撤销。
  **代价（明确记录）：** 发送侧不再有框架级内存上界，快发送方不再被自然节流。若实测出现发送侧内存增长或需更高吞吐控制，应以"有界发送缓冲阈值背压"作为独立能力重新评审。落点 RT_TRANSPORT_008 原条删除、§3.1.2.4、§3.4.4。

- **D6（TCP 客户端内部结构）：** `TcpClientTransport` 内部改为**连接泵 + 对外通道**：一条 connect-loop 协程持有 socket，建立连接后以流式读取器持续取数并投入对外通道；`Read` 即从该通道取。断链时**不向调用方发出任何信号**——connect-loop 转入重连，`Read` 因通道无数据而自然挂起，重连成功后新链路数据到达即被唤醒（D1 完全透明）。通道内断链前的残留字节保留并继续交付（其与新链路首字节可能拼成错帧，由编解码器重同步处置，见 D4）。
  `Write` **直接操作当前 socket**，重连期间立即返 `kConnection`（RT_TCP_RECONNECT_003 明确要求不缓存等待重连），不经该通道。
  **已知缺口（本轮接受，留待性能硬化期）：** 对外通道使用无界队列。字节流介质不能 tail-drop（丢中段即帧错乱），正解是"有界且满时阻塞生产者"——使内核缓冲填满、背压经操作系统回传对端；本轮不实现。落点 §3.4.4 已知缺口。

- **D7（诊断面降级为具体方法）：** `Generation()`/`AttemptCount()`/`LastFailure()`/`NextAttemptTime()` 及 `ApplyConfig` 随 `IConnectionObservable` 取消而降级为 `TcpClientTransport` 的具体方法，不进基类、不构成任何多态缝。运行时重配置能力（RT_TCP_RECONFIG 全组）保留不变。

- **D8（分层维持）：** 维持 `TcpTransport`（已连接 socket 上的收发）与 `TcpClientTransport`（连接管理）两层。`TcpTransport` 仍服务 TCP 服务端已接受连接与全部测试替身；合并只会复制收发逻辑而不消除复杂度。TCP 服务端的独立化留待后续单独评审。

## 影响（Consequences）

- **正面：** 交互层对 TCP/UDP/串口使用**同一段读循环**——无能力探测、无 reactor 协程、无代际概念、**无链路中断分支**（读循环仅需区分 `kClosed` 与其余）；删除 `IConnectionObservable`、`RunReactorLoop` 及其专属同步件；"链路可用性"成为所有介质一致的可观测事实。
- **负面（明确接受）：** ① 发送侧与重连传输的对外通道均失去内存上界（D5、D6），需在性能硬化期复核；② 断链后在途请求至多滞留一个总超时（D3），故总超时缺省值成为强制项；③ 丢弃归因由七项减六项，`loss=0` 验证 harness 须同步改写；④ 断链前的半帧残尾与新链路首字节可能拼成错帧，依赖编解码器重同步恢复（D4）。
- **对 ADR-0002：** 其 **D2 被本 ADR D5 撤销**；其 **D3′ 被本 ADR D2 重划边界**（连接管理仍不下沉，链路可用性上移）。其余决策不变。
- **对 ADR-0003：** 其 **D11**（连接管理分层）中"node 检测可选观察面后起 reactor 做代际隔离"部分被本 ADR D2/D3 取代；分层结论（外层管连接、内层管收发）由 D8 维持。

## 备选方案（Alternatives considered）

- **合并 `TcpClientTransport` 与 `TcpTransport` 为单类**：否决——复杂度在连接管理而非分层，合并要复制 397 行收发语义，制造重复而非消除复杂（D8）。
- **取消自动重连、断链即节点终结**（连接生命=节点生命，与 UDP/串口一致）：否决——可使 `TcpClientTransport` 缩到约 200–300 行且交互层零特例，但把重连责任整体转嫁宿主（每次断线需重建节点并重新装配 codec/handler/config，且各家自写退避），总复杂度不降反升，且报废 RT_TCP_RECONNECT 与 RT_TCP_RECONFIG 两个完整需求组。
- **以 `Read` 返回一次 `kConnection` 承载链路中断信号**：曾作为 D1 的中间方案，在 D3（撤销在途请求隔离）与 D4（撤销编解码器重置）先后定案后**失去全部用途**——交互层收到该信号无事可做，故最终取完全透明（见 D1 取舍记录）。
- **对外通道用现有 `BoundedQueue`（有界 + tail-drop）**：否决——对字节流丢中段即帧错乱（不同于 DDS 丢完整样本可接受）。有界且满时阻塞才是正解，本轮以无界暂代并记录缺口（D6）。
